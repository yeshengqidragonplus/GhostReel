# M6 结论

状态:**定稿**(2026-11-15,用户确认)· 对应设计文档 §11 的 M6:预览页,本地 WebGL 预览,和 Unity 渲染对比,完成标准"预览与引擎结果肉眼一致"。
设计决定、用法、接口、测试方法和踩过的坑见 [m6-notes.md](m6-notes.md)。

## 一句话结论

**`alphaclip preview clip.webm` 在浏览器里把片子画出来,和 Unity 画的对得上:同一块显卡上(RTX 4060),着色器输出与 Unity 逐字节相同,
叠到背景上之后任何像素最多差 1 个灰度级(Gamma 和 Linear 都是)。** 解码用的是引擎加载的同一份原生核心(本地服务,只监听 127.0.0.1),页面用新写的着色器主源
(`shaders/`,GLSL ES 3.0)按引擎的两步来画;页面上可以拖入文件、换背景、缩放、切 Gamma / Linear、改 sidecar 字段并导出。
"肉眼一致"这一条,我给的是数字和对比图(`build/m6-test-full-nvidia/compare/`,Unity | 预览 | 差 ×64),**最后要你自己打开页面看一眼才算数**。
**没有的:** Chromium 以外的浏览器、URP / UI 路径 / Unity 6 / 真机上的对比、真实素材和大分辨率、播放性能、着色器生成脚本(Unity 的着色器仍是手写的)、
`keyed` 和边缘参数(M7),详见"没覆盖到的"。

- **页面和 Unity 对精确真值的误差是同一组数**(浏览器在 RTX 4060 上):

| | 全图平均绝对误差 | 软边带符号均值 | 对照 |

| Gamma | 0.13 – 0.28 | −0.03 … +0.06 | −19.2 … +21.2 |

## 一个事后加的判据

"和 Unity 一样"的判据是看数据之前定的:任何像素最多差 2 级,平均不超过 0.1 级。同一块显卡上远在其内。
**浏览器用 Intel 集成显卡时,Linear 下有 16 个值(622 万分之十六)差到 3,超出了这条判据。** 查到的原因是显卡之间的差别,不是预览页和 Unity 的差别:
接近黑色处 sRGB 曲线很陡,硬件"解码 → 混合 → 编码"的精度各家不同;同一个像素(蓝 = 2、alpha 254、叠在白上)按公式是 14,RTX 4060 上的浏览器和 Unity 都给 16。
测试里因此给"换了显卡的 Linear"另设了一档(最多 4 级,超过 2 级的值不超过万分之一)。**这一档是看到数据之后定的**,请按这个身份看待它;
Gamma 和"同一块显卡"的判据没有动过。同理,"合成对 CPU 混合"在 Linear 下从"最多 1 级"放宽为"最多 2 级且超过 1 级的值不超过万分之一"(RTX 4060 上 1620 万个值里 71 个差 2)。

## 没覆盖到的(请不要把上面的结论外推到这些)

- **浏览器:** 只有 Chromium 系,而且都是无头模式在 Windows 上。Firefox、Safari 没有测(本机没有装 Firefox)。有窗口的浏览器里我只手动看过页面(Claude 的内置浏览器),没有跑自动测试。
- **和 Unity 的对比范围:** 只有 Unity 2022.3.62f2、内置管线、编辑模式的场景路径(相机 + 四边形 + `AlphaClip/UnlitPremultiplied`)。
  **URP、UI 路径(RawImage)、Unity 6、播放器构建、Pixel 6a 都没有和预览页比过。**
- **素材:** 对比用的是 M4 的四个合成片(320×180)的第 0、20、40 帧。真实素材、大分辨率、长片没有测;`encode` 生成的片子没有专门拿来对比(它们和 M4 的片子是同一个形状)。
- **放大:** 和 Unity 的对比都是 1:1。放大只在预览页内部验证过(最近点 = 像素重复;双线性落在相邻像素之间),没有和 Unity 里放大的四边形比;
  M5 留下的"GPU 上放大后的暗圈"也没有借这次机会去量。
- **"肉眼":** 测试比的是帧缓冲里的字节,不是屏幕上的光;浏览器和 Unity 各自的显示色彩管理不在测试范围内。完成标准里的"肉眼"要你看了才算。
- **性能:** 没有量。每一帧是一次本机 HTTP 请求;320×180 和 640×360 的样本片播放正常(D 部分检查了"每一帧都按顺序出现、速度对"),1080p 能不能实时播没有试。
- **POSIX:** HTTP 服务的 POSIX 分支和打开浏览器的 `xdg-open` / `open` 分支只编译过(Android arm64 交叉编译),没有运行过。`preview` 的所有测试都在 Windows 上。
- **新 C++ 代码没有消毒器运行:** HTTP 服务和 `preview` 只有 300 例变异请求加手写的畸形请求,没有 ASan / UBSan,没有覆盖率引导的模糊测试,也没有专门的安全评审。
  它只监听回环地址并检查 Host / Origin,但请仍把它当作"开发时在自己机器上用的工具",不要放到别人能访问的地方。
- **没做:** 着色器生成脚本(设计 §8.3);Unity 的着色器没有改成从主源生成,两份靠测试对齐。WebAssembly 核心(页面不能脱离 exe)。
  `keyed`、边缘后处理和它们的参数(M7)。页面上的 `verify`。音频。
- **M4、M5 的剩余项仍然开着**(Pixel 6a、Unity 6 等),M6 没有补。Unity 包里的 `.dll` / `.so` 仍是 M4 同步的那份。
